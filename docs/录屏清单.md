# 录屏清单（DSHA 宣传片 v2 · 交委托人录制）

> 用途：宣传片 v2 的真实录屏素材采集规范。分镜与帧数以 [`docs/storyboard.md`](storyboard.md) 为准，本清单是它的拍摄版；
> 录屏文件命名与 [`src/timeline.ts`](../src/timeline.ts) 的 `asset` 字段一一对应（`recordings/xx-xxx.mp4`）。
> 素材缺失时成片回退代码 mock（timeline 已有 fallback），但真实录屏质感优先。
> 字幕口径数字以 [`docs/facts.md`](facts.md) 为准，录屏画面本身不要出现任何带数字的"宣传语"截图。

---

## 一、全局规范（每段都适用）

### 1. 隐私零容忍（最重要，违即重录）

- 画面**不得出现**：API Key、token、邮箱、个人路径、真实个人文件名、日志密钥。
- **Web GUI**：使用事先准备好的干净会话 / 假对话 / 无关内容，不要录真实历史会话（历史里可能有个人文件与配置）。
- **终端**：只用无害示例命令；避免展示 home 目录内容（如 `ls ~` 一类动作不要做）。
- **录屏前检查**：下拉通知栏看一眼，清掉敏感通知或开勿扰；看状态栏，确认无私人账号/消息提示。
- **录完自查**：上传前完整看一遍该段，发现敏感画面立即重录该段，不要抱侥幸心理。

### 2. 画质

- **竖屏录制**，分辨率 1080p 或更高。
- 手机稳固放置（支架或倚靠），避免手抖；环境光充足、屏幕亮度充足（建议关掉自动亮度，避免忽明忽暗）。
- **悬浮条保持开启状态**（按日常习惯设置即可，不要为录制专门改设置）。
- 用系统自带录屏工具即可，帧率默认（30/60 均可）。

### 3. 节奏

- 每段录制 **12-20 秒**（成片每段只用几秒，多拍是给剪辑留余量）。
- **每个动作之间停留约 1 秒**——既是剪辑切点，也让观众看清界面。
- 一条不满意可以重拍多条，命名不变，上传时覆盖即可。

### 4. 环境纪律

- **不为录制改动环境**：不卸载 DSHA、不清理数据、不改系统设置、不删任何文件；拍完即走。
- 两个例外（涉及"重装/卸载"画面，**需委托人先拍板**，见第四节）：01 冷启动、08 备份。

### 5. 命名与上传

- 命名规范：`01-coldstart.mp4` … `10-plugins.mp4`（与 `src/timeline.ts` 的 `asset` 字段一致）。
- 上传方式（二选一）：
  1. GitHub 手机网页直接上传到 `public/recordings/`（仓库页 → Add file → Upload files）；
  2. 把文件传给 Lead 代提交。
- 上传后告知 Lead，由 Lead 跑 `scripts/validate-recordings.mjs` 校验入库（本地无 ffmpeg，深度检查分辨率/时长/有声由 CI 负责）。

## 二、分段拍摄规范（10 段）

### 01-coldstart.mp4 — Hook · 装完即用（场景 s0-hook）

- **拍什么**（动作分解，动作间停留 1s）：
  1. 手机桌面亮屏，能看到 DSHA 图标（停 1s）；
  2. 点击 DSHA 图标启动；
  3. 首次启动的解压环境进度条（停 2-3s，让进度可见）；
  4. 进入 READY 页（停 1-2s）。
- **录制时长**：12-20s · 竖屏。
- **字幕/旁白用意**：字幕"免 ROOT · 免 Termux · 装完即用"；旁白"免 Root、免 Termux，装完即用。"——核心是"点一下就进 READY，零命令行"。
- ⚠️ **本机已安装 DSHA（v0.1.7-alpha2low），无法重演"装 APK → 首次解压"**。优先用备用干净设备 / 模拟器录制；若不可得，本段允许回退 mock（timeline 已有 fallback），请委托人确认（见第四节）。

### 02-webgui.mp4 — 能力一击 · Web GUI（场景 s1a-webgui）

- **拍什么**：
  1. 打开 Web GUI（127.0.0.1:3080，App 内入口或浏览器均可）（停 1s）；
  2. 新建一个干净会话，输入事先准备的无害问题（如"用 Python 写个快速排序并解释"）；
  3. 智能体流式写出代码 / 读取文件（停留到输出完成）；
  4. （可选）让智能体执行一条只读命令展示 Ubuntu 环境（如 `cat /etc/os-release`）。
- **录制时长**：12-20s · 竖屏。
- **字幕/旁白用意**：字幕"完整 Ubuntu 24.04 · apt 随便用"（口径：README · 2026-09）；旁白"完整 Ubuntu 24.04，apt 随便用。"——展示 harness 本体的对话与流式输出。
- **隐私要点**：只用准备好的假对话；不展示真实会话列表里的个人内容。

### 03-terminal.mp4 — 能力二击 · proroot 性能（场景 s1b-terminal）

- **拍什么**：
  1. 打开内置终端（停 1s）；
  2. 真实安装一个小软件：`apt install -y sl`（下载与安装输出要可见）；
  3. 运行 `sl`（小火车动画，画面生动）；
  4. 运行 `neofetch`（显示 Ubuntu 24.04 系统信息，呼应字幕）；
  5. 运行 `htop` 几秒（完整进程视图）；
  6. （可选）vim 打开一个演示文件 `demo.txt`，输入几行无关内容保存退出。
- **录制时长**：12-20s · 竖屏。
- **字幕/旁白用意**：字幕"proroot 零 ptrace 开销，关键项实测 +58%"（口径：README（vivo V2352A / Android 14）· 2026-09）；旁白"proroot 零 ptrace 开销，关键项实测快百分之五十八。"——用 apt/vim/htop 真跑证明"不是裁剪版"。
- **隐私要点**：只用上述无害示例命令；vim 内容用通用演示文本；不要展示 home 目录文件列表。

### 04-floating.mp4 — 能力三击 · 流式悬浮条（场景 s1c-floating）

- **拍什么**：
  1. 停在某界面，确认悬浮条已开启（停 1s）；
  2. 触发一个多步 / 长输出的任务（让智能体连续执行几条命令，或跑一个持续输出的命令）；
  3. 悬浮条贴屏幕顶部滚动显示命令原文与输出（停 3-5s，这是本段主体）；
  4. （可选加分）展示一次悬浮条参数调节（底色 / 透明度 / 行数）。
- **录制时长**：12-20s · 竖屏。
- **字幕/旁白用意**：字幕"AI 输出，实时上屏"；旁白"AI 的输出，实时贴上屏幕顶。"——悬浮条是 DSHA 的标志性画面，务必拍清楚"贴顶滚动"。
- **隐私要点**：流式内容同样不能含 token / 个人路径——用准备好的无害任务触发。

### 05-adb.mp4 — 高潮 · ADB 直连（场景 s2-adb，成片 15s，全片重点）

- **拍什么**：
  1. 打开 DSHA 的 ADB 配对入口（停 1s）；
  2. 系统"开发者选项 → 无线调试 → 配对"过程（配对码为动态生成，入镜无长期风险；不要特写任何已保存的密码字段）；
  3. 配对成功 / 保活提示（停 1s）；
  4. 在 Web GUI 或终端里让智能体远程操作本机：**点击屏幕某处 → 滑动 → 截屏本机 → 读日志**（每个动作之间留足时间，截屏结果要能在对话里看到）；
  5. （可选）读当前屏幕内容并描述（screen-ocr 效果）。
- **录制时长**：12-20s · 竖屏。
- **字幕/旁白用意**：字幕"配一次 ADB，agent 直接操作这台手机"（口径：README · 2026-09）；旁白"配一次 ADB，智能体直接操作这台手机：点击、滑动、截屏、装应用，不需要 Shizuku。"
- **隐私要点**：远程截屏会拍下状态栏/通知栏——操作前确认通知栏干净；被智能体点击/滑动打开的 App 用无关应用（如设置页、计算器），不要打开含个人信息的 App。
- **旁白与画面的缺口**：旁白提到"装应用"，但"安装后再卸载"属于为录制改动环境。建议实录只拍点击/滑动/截屏/读日志四件，"装应用"画面由代码 mock 或 C 方案补充（需委托人确认，见第四节）。
- **C 方案补充位**：`public/recordings/c-adb/` 预留为截屏序列目录（DSHA 设备能力批量截屏 + CI ffmpeg 推拉动效）。该方案涉及操作手机，**待 Lead 确认后执行**，当前为待命状态。

### 06-vscreen.mp4 — 高潮 · 实验性虚拟屏（场景 s3-vscreen）

> **外部提供，等待中（委托人安排他人录制）**

- 本机为 Low 版构建，实测不支持虚拟屏（create 返回 VSCREEN_UNSUPPORTED_LOW），无法录制；素材由委托人安排他人用 Standard 版设备录制后提供。到位前审片版显示占位框，母版门禁点名该文件。

### 07-guard.mp4 — 信任 · 危险命令守门人（场景 s4a-guard）

- **拍什么**：
  1. 打开内置终端（停 1s）；
  2. 输入一条必然被拦截的危险命令（如 `rm -rf /`，守门人按模式拦截，不会真删）；
  3. 拦截提示出现：前台弹窗 / 通知 / 悬浮条（三渠道形态都拍到更好）；
  4. **选择【拒绝】**——证明"危险操作你说了算"；
  5. （可选）换一条命令再演示一次拦截→拒绝。
- **录制时长**：12-20s · 竖屏。
- **字幕/旁白用意**：字幕"危险操作，你说了算"；旁白"危险操作，你说了算。"——拦截→用户批准的闭环，"批准"环节用拒绝来演示，严禁真点批准。
- **隐私要点**：拦截弹窗展示的命令原文不要带个人路径。

### 08-backup.mp4 — 信任 · 数据不丢（场景 s4b-backup）

- **拍什么**：
  1. 打开数据与备份页（停 1s）；
  2. 选择分范围备份中的一项（如"只对话"），执行备份（进度可见）；
  3. 恢复前的 CRC 体检预览界面（逐项校验状态，停 1-2s）；
  4. （可选）备份范围选项界面展示（全量 / 只对话 / 只插件）。
- **录制时长**：12-20s · 竖屏。
- **字幕/旁白用意**：字幕"卸载重装，数据不丢"（口径：README · 2026-09）；旁白"卸载重装，数据不丢。"——分范围备份 + 恢复前体检。
- ⚠️ **不真实卸载重装 DSHA**（违反环境纪律且有数据风险）。"卸载→重装→数据还在"的连续画面如必须上片，请委托人决策：另择时机在可牺牲环境演示，或用代码 mock / 示意图替代（见第四节）。
- **隐私要点**：备份文件列表、路径显示如入镜，确认无个人敏感信息，不要特写文件管理器。

### 09-selfcheck.mp4 — 信任 · 自检与自愈（场景 s4c-selfcheck）

- **拍什么**：
  1. 打开自检页（停 1s）；
  2. 开始 23 项体检，逐项跑过（可适度连续拍，保留几项结果特写）；
  3. 如有失败项：点"一键修补"，拍修复过程与修复后的复查结果（真实更有说服力）；
  4. 自检报告总览（停 1-2s）。
- **录制时长**：12-20s · 竖屏。
- **字幕/旁白用意**：字幕"23 项自检，一键修补"（口径：README · 2026-09）；旁白"坏了，它说清哪坏了。"——自检说清问题 + 一键修。
- **隐私要点**：自检详情与日志**不得出现 token、密钥、个人路径**；录前先手动跑一次自检，肉眼确认报告内容干净再录。

### 10-plugins.mp4 — 生态 · 插件市场（场景 s5a-plugins）

- **拍什么**：
  1. 打开插件管理页（停 1s）；
  2. 浏览插件市场：列表滚动，出现内置插件（device-shell / screen-ocr-operator / dsh-web-mobile 等）；
  3. 安装一个轻量插件（安装进度 → 完成）；
  4. 启停演示：停用一个再启用；
  5. 打开 dsh-web-mobile 移动端 UI：窄屏单栏 + 目录抽屉开合（停 1s）。
- **录制时长**：12-20s · 竖屏。
- **字幕/旁白用意**：字幕"插件生态，全部在 App 内完成"（口径：dsh-web-mobile 3.0.1 · 2026-09）；旁白"插件生态，浏览、安装、启停，全部在 App 内完成。"
- **隐私要点**：不要打开第三方插件的配置页（可能有 token 输入框）；只装无害轻量插件。

## 五、入库校验

素材上传后由 Lead 执行：

```bash
node scripts/validate-recordings.mjs
```

校验内容：命名白名单、文件存在且非空、大小 sanity（>200KB 且 <300MB）、扩展名 mp4；输出通过/缺失/异常清单，exit code 反映缺失。
**本地无 ffmpeg**：分辨率 / 时长 / 有声审计等深度检查由 CI 负责（脚本注释内有说明）。
